# 신구대조전 — 교범 신·구 비교 도구

> 번호가 밀려도, 바뀐 조항만 정확하게.
> 교범 개정의 **수정 제안 수집 → 심의 → 반영 → 신·구 대조 → 대비표·최종본 → 결재 보고**를 하나의 도구로 잇는 웹 애플리케이션

- 배포: https://projecthmk.vercel.app (작성자 도구 `/author`, 제안서 `/propose`)
- 저장소: https://github.com/hmkim-beta/project_hmk
- 형태: HTML 파일 3개 (홈 · 작성자 도구 · 제안서). 설치·서버 없이 브라우저로 열면 동작하며, 인터넷이 없는 폐쇄망에서도 쓸 수 있음

---

## 1. 어떤 문제를 해결하는가

### 현장의 업무 흐름
군 교범(훈령) 개정은 다음 순서로 진행됩니다.

```
일선부대 수정 제안(한글 양식) → 담당자 엑셀 취합 → 심의(반영 여부 결정)
→ 신규 교범 작성 → 신·구 비교 → 신·구 대비표(한글) 작성 → 검토·결재
```

이 과정의 상당 부분이 **두 문서를 나란히 띄워 눈으로 대조하고 복사·붙여넣기**하는 수작업이었습니다.

### 해결한 문제

| 문제 | 현장에서 생기는 일 | 신구대조전의 해결 |
|---|---|---|
| **변경 누락** | 바뀐 곳을 눈으로 찾다가 빠뜨려, 검토 단계에서 대비표를 다시 작성 | 조항 단위로 자동 비교해 추가·삭제·수정·이동을 **빠짐없이** 색으로 표시 |
| **조항 대응의 어려움** | 조항 하나가 신설·삭제되면 뒤 번호가 모두 밀려, 어떤 조항끼리 비교해야 하는지 혼동 | 번호가 아니라 **제목과 내용의 유사도**로 짝을 지어, 번호가 밀려도 같은 조항을 찾아냄 |
| **제안 취합 수작업** | 부대마다 제각각인 양식을 엑셀로 옮기며 전사 오류 발생 | 표준 제안서로 받아 **한 번에 불러와 종합 엑셀**로 정리 |
| **제안 반영 작업** | 채택한 제안을 교범에서 찾아 하나씩 고침 | 심의 결과에 따라 제안 문구를 교범에서 찾아 **자동 반영**하고, 못 찾은 것만 직접 처리 |
| **보고 자료 작성 부담** | 개정 규모와 성격을 결재권자에게 요약하는 일이 별도 작업 | 장별·유형별 통계와 **통계 기반 총평 초안**을 자동 작성 |

### 지켜야 했던 제약
- **폐쇄망(국방망)**: 인터넷이 없고 새 서버를 구축할 수 없음 → 외부 라이브러리 없이 HTML 파일만으로 동작
- **한글 문서**: 교범 원본이 HWPX·HWP → 두 형식을 브라우저에서 직접 해석하고, 결과를 다시 한글 파일(HWPX)로 저장
- **보안**: 교범 내용이 외부로 나가지 않아야 함 → 모든 처리를 사용자 PC의 브라우저 안에서 수행

## 2. 주요 기능

### ① 신·구 조항 자동 비교 (핵심)
- **HWPX·HWP를 그대로 읽음**: 한글 파일을 변환 없이 올리면 본문·표·그림 캡션을 추출
- **조항 자동 분할**: 장·절·조(항), 부칙, 별표·별지를 인식하고, 앞쪽 목차는 자동으로 건너뜀. 번호 패턴은 설정에서 수정 가능
- **번호 밀림에 강한 매칭**: 문서 순서를 유지하는 정렬(LCS 계열 동적 계획법)에 텍스트 유사도를 결합해 짝을 짓고, 순서를 벗어난 조항은 **이동**으로 판정
- **글자 단위 변경 표시**: 지운 글자는 빨간 취소선, 더한 글자는 초록 밑줄. "번호 변경: 1-3 → 1-4" 배지
- **보기 전환**: 변경만 보기 / 전체 보기, 장·절 목차와 장별 변경 건수
- **표기 차이 무시 옵션**: 가운뎃점(·, ㆍ, ․) 차이나 띄어쓰기 차이를 변경으로 보지 않게 설정
- **수동 보정**: 잘못된 짝은 연결 해제, 원하는 조항끼리 수동 연결 (다시 매칭해도 유지)

### ② 대비표와 최종본
- **변경 사유·관련 제안번호** 입력
- **대비표 엑셀** 내보내기, **대비표 복사**(바뀐 부분에 밑줄이 들어간 표로 복사 → 한글에 바로 붙여넣기)
- **직접 수정**: 개정 내용을 화면에서 고쳐 최종본으로 저장
- **최종본 HWPX 저장**: 원본 HWPX의 서식·표·그림·쪽 설정은 그대로 두고 **바뀐 글자만** 고쳐 한글 파일로 저장 (굵은 조 제목 등 글자 모양 유지)

### ③ 수정 제안 수집·심의
- **제안서(제안자용)**: 위치(페이지·장절항·표·그림), 구분, 현행 내용, 수정 제안, 근거, 이미지 첨부. 큰 이미지는 자동으로 줄임
- **보내는 방법 두 가지**: 파일(.json)로 저장해 메일·공유폴더로 전달하거나, 온라인 배포 시 **[온라인 제출]**로 바로 전달
- **제안 종합(작성자용)**: 여러 파일을 한 번에 불러오기, 구분·심의 결과로 거르기·정렬, 첨부 이미지 미리보기, 심의 결과(반영·부분반영·미반영)와 사유 입력, **종합 엑셀**과 첨부 이미지 ZIP 내보내기

### ④ 수정 반영
- 심의 결과가 적힌 **종합 엑셀 + 현재 교범**을 올리면, 반영하기로 한 제안의 '현행 내용'을 교범에서 찾아 '수정 제안'으로 바꿈 (띄어쓰기·가운뎃점 차이를 무시하고 찾음)
- 제안마다 **반영됨 / 직접 수정 필요 / 위치 확인 필요 / 제외** 상태 표시, 못 찾은 제안은 대상 조항을 골라 직접 반영
- 결과를 **신·구 비교로 보내** 대비표와 최종본으로 이어 감

### ⑤ 종합 평가 (결재 보고용)
- 기존·신규 조항 수, 유형별 변경 건수와 비율, **장별 변경 막대 차트**, 변경 폭이 큰 조항 Top 10, 표·그림 변경 목록, 제안 반영률
- **통계 기반 총평 초안**: LLM 없이 통계만으로 개정 개요·주요 변경·제안 반영 결과·검토 시 유의 사항(사유 미입력 조항, 미심의 제안, 조항 인용 확인 등 자동 점검)을 보고서 문체로 작성
- **LLM 요청문 TXT·PDF 내려받기**: 폐쇄망 LLM이 마련되면 요청문을 넣어 총평을 다듬는 수동 처리 지원 (직접 연결 코드는 준비되어 주석 처리)
- 리포트 엑셀, 인쇄

### ⑥ 처음 쓰는 사람을 위한 샘플 체험
- **작성자용**: 가상 교범 2권(변경 10건)과 제안 6건으로 10단계 안내를 따라 전 과정을 연습. 체험 데이터는 실제 작업과 분리 저장
- **제안자용**: 완성된 작성 예시와 작성 요령. 예시는 제출되지 않고, 쓰던 내용은 보관 후 복원

### ⑦ 작업 보존
- 브라우저 자동 저장(IndexedDB) + **작업 파일(.json) 백업·불러오기**로 PC를 옮겨도 이어서 작업

## 3. 현장 활용 시나리오

### 시나리오 A — 일선부대 사용자: 수정 제안 보내기
> 교범으로 교육하던 ○○대대 중사가 표의 담당자가 실제 부대 운영과 다르다는 것을 발견합니다.

1. 홈에서 **[작성 예시 보기]**로 어떻게 쓰는지 확인
2. 제안서에 위치(7쪽, 2-2, 표 2-1), 현행 내용("부소대장"), 수정 제안("분대장"), 근거, 현장 사진을 입력
3. **[온라인 제출]** → 접수번호를 받음 (폐쇄망에서는 **[제안 파일 저장]** 후 메일·공유폴더로 전달)

### 시나리오 B — 교리연구 담당관: 제안 심의와 반영
> 개정 주기를 맞아 담당관이 여러 부대의 제안을 모읍니다.

1. [제안 종합]에서 제안 파일을 한꺼번에 불러오거나 **[온라인 제안 불러오기]**
2. 제안을 하나씩 열어 첨부 이미지까지 확인하고 **반영·부분반영·미반영**과 사유 입력 → **종합 엑셀**로 심의 자료 작성
3. [수정 반영]에 종합 엑셀과 현재 교범을 올려 **채택된 제안을 교범에 자동 반영**, 못 찾은 제안만 직접 고침

### 시나리오 C — 교리연구 담당관: 신·구 대비표 작성
> 신규 교범 작성을 마치고 결재용 신·구 대비표를 만들어야 합니다.

1. 기존 교범과 신규 교범 HWPX를 올림 → 조항 하나가 신설되어 번호가 밀렸지만 **같은 조항끼리 자동으로 짝**
2. **[변경만 보기]**로 바뀐 조항만 훑으며 변경 사유 입력, 잘못 짝지어진 조항은 수동 연결로 바로잡음
3. 수정이 더 필요한 문구는 카드에서 **[수정]**으로 고쳐 최종본에 반영
4. **[대비표 복사]** → 한글 대비표 양식에 붙여넣기, **[최종본 저장]** → 서식이 유지된 HWPX 확보

### 시나리오 D — 결재 보고
> 과장에게 이번 개정의 규모와 핵심을 보고해야 합니다.

1. [종합 평가]에서 장별 변경 차트, 변경 폭 Top 10, 제안 반영률 확인
2. **[통계 기반 초안 작성]**으로 총평 초안을 만들고 "주요 개정 방향"을 다듬음
3. 리포트 엑셀·인쇄로 보고 자료 완성 (폐쇄망 LLM이 있으면 요청문 TXT·PDF로 문장을 다듬음)

### 시나리오 E — 신규 담당자 교육
> 담당자가 바뀌어 새 담당자가 도구를 처음 씁니다.

- 작성자 도구의 **[샘플 체험]**에서 10단계 안내를 따라 15분 정도 전 과정을 연습. 실제 작업에는 영향 없음

## 4. 검증 결과

| 검증 | 결과 |
|---|---|
| 정답지가 있는 가상 교범 (번호 밀림·추가·삭제·수정·이동·표·그림 변경 10건) | **10건 모두 검출**, 번호만 바뀐 조항 4개는 '동일 + 번호 변경'으로 정확히 분류 |
| 실제 훈령 신·구 비교 vs 공식 신·구조문대비표 (CSRP 훈령) | 대비표의 **18개 항목 모두 검출**, 대비표에 빠진 실제 차이 5건(띄어쓰기 등)도 발견 |
| 최종본 HWPX 저장 | 한글 2024에서 열어 **의도한 변경만 반영**되고 서식이 유지됨을 확인 (텍스트 추출 비교·페이지 이미지 확인) |
| 온라인 제출·수집 (Supabase) | 공개 키로는 **추가만 가능하고 읽기 차단**, 작성자 접근 키로만 조회됨을 실제 프로젝트에서 확인 |
| 폐쇄망 동작 | 설정 파일이 없으면 오프라인 모드로 전환, 통계 기반 총평 등 외부 요청 0회 |

## 5. 기술 구성

| 영역 | 내용 |
|---|---|
| 프런트엔드 | 순수 JavaScript·HTML·CSS (프레임워크·외부 라이브러리 없음), 반응형 |
| 문서 해석 | ZIP·Deflate 해제, HWP(OLE 복합 문서·레코드 구조) 파서, HWPX(XML) 파서를 직접 구현 |
| 비교 알고리즘 | 바이그램 유사도 + 순서 보존 정렬(DP) + 이동 탐지, 줄·글자 단위 diff |
| 문서 생성 | XLSX 생성기, ZIP 생성기, HWPX 부분 수정기(원본 run 구조를 유지한 글자 치환) 직접 구현 |
| 저장 | IndexedDB 자동 저장, JSON 작업 파일 |
| 온라인(선택) | Vercel 정적 배포(GitHub 연동 자동 배포), Supabase(PostgreSQL + RLS, 작성자 접근 키 해시 검증 함수) |
| 빌드 | Python 스크립트로 원본을 HTML 파일 3개로 묶음 (로고·샘플 데이터 포함) |

## 6. 만든 사람의 역할과 배운 점 (작성 예시 — 본인 경험에 맞게 고쳐 쓰세요)

- 현업의 PRD(요구사항 정의서)를 바탕으로 **폐쇄망·한글 문서라는 제약 안에서** 동작하는 구조를 설계
- 공식 신·구조문대비표를 정답지로 삼아 **실제 훈령 문서로 정확도를 검증**하고, 목차 오인식·가운뎃점 표기 차이 같은 현장 문서의 문제를 반복 개선
- 교범 내용 보호를 위해 **데이터가 외부로 나가는 지점(온라인 제출, LLM)을 최소화·선택화**하고, 공개 키 권한을 '추가만'으로 제한
