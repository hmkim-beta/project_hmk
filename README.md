# 교범 신·구 비교 도구 (MVP)

인터넷 없이 HTML 파일만 열어 쓰는 도구입니다. 외부 라이브러리를 쓰지 않으며, 모든 처리는 브라우저 안에서만 이루어집니다.

사이트 이름은 **신구대조전**입니다.

| 파일 | 사용자 | 용도 |
|---|---|---|
| `index.html` | 모두 | 홈. 작성자용·제안자용 입구 |
| `교범비교도구.html` | 교범 작성자 | 신·구 비교, 제안 종합, 수정 반영, 종합 평가 |
| `수정제안폼.html` | 수정 제안자 | 제안 작성 후 `.json` 파일로 저장 |

배포할 때는 이 세 HTML 파일을 같은 폴더에 복사하면 됩니다(로고도 파일 안에 들어 있음). Chrome이나 Edge로 `index.html`을 여세요. 두 도구의 왼쪽 위 로고를 누르면 홈으로 돌아갑니다.

## 처음 쓰는 사람을 위한 샘플 체험

- **제안자**: 홈의 [작성 예시 보기] 또는 제안서 화면의 **[작성 예시 보기]** → 완성된 예시 제안서(2건, 스케치 첨부)와 작성 요령이 보입니다. 쓰던 내용은 따로 보관됐다가 [예시 닫고 직접 쓰기]를 누르면 돌아옵니다. 예시는 온라인 제출되지 않습니다.
- **작성자**: 홈의 [샘플로 체험하기] 또는 작성자 도구의 **[샘플 체험]** → 가상 교범 2권(변경 10건)과 샘플 제안 6건(심의 결과 포함)이 들어간 상태로 열리고, 오른쪽 아래 **10단계 안내**가 신·구 비교 → 짝 고치기 → 직접 수정 → 대비표 → 제안 심의 → 수정 반영 → 종합 평가 화면으로 차례로 안내합니다.
- 체험 중 작업은 브라우저에 **따로 저장**되어 실제 작업과 섞이지 않습니다. [체험 끝내기]를 누르면 원래 작업으로 돌아갑니다.
- 샘플 데이터는 도구 파일 안에 들어 있어 **내부망에서도** 체험할 수 있습니다. (`samples/`를 고친 뒤 `python src/build.py`)

## 온라인 제안 제출 (Vercel + Supabase, 선택)

Vercel에 배포하고 Supabase를 연결하면 제안자가 폼에서 **[온라인 제출]**로 바로 보내고, 작성자는 [제안 종합]의 **[온라인 제안 불러오기]**(작성자 접근 키 필요)로 가져올 수 있습니다. 교범 파일은 여전히 PC 밖으로 나가지 않습니다. 설정(`config.js`)이 없으면 지금처럼 오프라인(.json 파일)으로 동작합니다.

설정 방법: [`docs/배포_Vercel_Supabase.md`](docs/배포_Vercel_Supabase.md) · DB 설정: [`supabase/schema.sql`](supabase/schema.sql)

## 입력 파일

- HWPX를 기본으로 읽고, HWP(5.0)도 읽습니다. 암호가 걸렸거나 배포용으로 저장한 HWP는 읽지 못합니다.
- 조항 번호 패턴(제N장, 제N절, 제N조, N-N., 별표·별지 등)은 [설정]에서 고칠 수 있습니다.

## 수정 반영 탭

- 심의 결과를 적은 **종합 엑셀**과 **현재 교범**을 올리면, 반영 범위(기본: 반영·부분반영)에 든 제안의 '현행 내용'을 교범에서 찾아 '수정 제안'으로 바꿉니다. 띄어쓰기·가운뎃점·따옴표 차이는 무시하고 찾습니다.
- 구분이 '삭제'이고 수정 제안이 비어 있거나 "삭제"이면 현행 문구를 지웁니다.
- 찾지 못한 제안은 위치 칸(조항 번호, 표·그림 번호)으로 대상 조항을 추정하거나 작성자가 고르고, 조항 카드의 [수정]으로 직접 반영합니다.
- [신·구 비교로 보내기]를 누르면 현재 교범을 '기존', 반영본을 '신규'로 놓고 반영 내용과 사유·제안번호를 넘겨 대비표로 이어 갑니다.

## 최종본을 한글(HWPX)로 저장

[신·구 비교]의 **최종본 저장**과 [수정 반영]의 **반영본 저장**에서 HWPX 또는 텍스트를 고를 수 있습니다.

- **원본이 HWPX**: 원본 파일을 그대로 두고 바뀐 글자만 고칩니다. 글꼴·문단 모양·표·그림·쪽 설정이 유지되고, 고친 글자는 원래 글자 모양(굵은 조 제목 등)을 따릅니다. 새 줄은 바로 앞 문단의 모양과 들여쓰기를 따릅니다.
- **원본이 HWP**: 서식 없이 글자만 담은 HWPX를 만듭니다. 서식을 살리려면 한글에서 원본을 HWPX로 저장해 다시 올리세요.
- 표는 칸 안의 글자 수정만 반영합니다. 표의 행 추가·삭제, 그림 삭제, 그림 속 글자는 반영하지 않고 저장 후 알려 줍니다.
- 이를 위해 올린 HWPX 원본을 브라우저 저장소와 작업 파일에 함께 보관합니다(작업 파일 크기가 원본만큼 커집니다).

## 작성자 총평 (통계 기반 · LLM 요청문)

[종합 평가] › 작성자 총평의 **[통계 기반 초안 작성]**은 LLM 없이 비교 통계로 총평 초안(개정 개요, 장별 변경, 주요 변경, 표·그림, 제안 반영, 검토 시 유의 사항)을 만듭니다. 폐쇄망에서도 동작합니다. 폐쇄망 LLM을 쓸 때는 **LLM 요청문 [TXT 내려받기]·[PDF 내려받기]**로 요청문을 받아 LLM에 넣고, 결과를 총평 칸에 붙여넣습니다. 폐쇄망 LLM 직접 연결 코드와 이전 Gemini 연결 코드는 주석으로 보관했습니다. 자세한 내용: `docs/LLM_연동_메모.md`

## 폴더 구성

- `src/home/index.html` : 홈 원본
- `src/author/` : 작성자 도구 원본 (index.html, style.css, js/)
- `src/form/form.html` : 제안자용 폼 원본
- `src/assets/` : 로고 (`tools/make_logo.py`로 원본 이미지에서 생성)
- `src/shared/cloud.js` : Supabase 연결(제안 제출·불러오기). 빌드 때 두 도구에 들어감
- `supabase/schema.sql` : Supabase 표·권한·작성자 읽기 함수
- `vercel.json`, `scripts/build-vercel.mjs` : Vercel 배포 설정 (배포 파일만 `dist/`로 모으고 `config.js` 생성)
- `config.example.js` : 온라인 설정 예시 (실제 `config.js`는 git 제외)
- `src/build.py` : 원본을 묶어 `index.html`, `교범비교도구.html`, `수정제안폼.html`을 만듭니다. 원본을 고친 뒤 `python src/build.py`를 실행하세요. (루트의 HTML을 직접 고치면 다음 빌드 때 덮어써집니다.)
- `samples/` : 시험용 가상 교범 HWPX 2개, 정답지, 제안 파일 3개
- `tools/make_samples.py` : `samples/`를 다시 만듭니다. 한글 자동화로 문단·표·그림을 넣어 한글이 직접 저장하므로, 실행하려면 한글과 pywin32가 필요합니다. 표·그림의 캡션은 개체 바로 앞 문단으로 들어갑니다.
- `tools/make_template.py` : 한글에서 저장한 빈 HWPX를 `src/author/assets/blank.hwpx` 틀로 정리합니다(작성자 정보 삭제).
